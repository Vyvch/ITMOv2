# Design

## Context

- **API.** `GET /api/domains` ([api.py](../../../api.py)) отдаёт весь список из `get_domains()`. Список кешируется на 1 час. Имена уже в нижнем регистре, `.рф` декодированы из punycode в кириллицу ([services.py](../../../services.py)).
- **Клиент.** Вся фильтрация происходит в [templates/index.html](../../../templates/index.html): `applyFilters()` применяет даты, затем `includes` по `searchQuery`, затем пагинацию по 100. Запрос приводится к нижнему регистру и обрезается.
- **Тесты.** Только Python `unittest` через `python scripts/check.py`. Runner менять нельзя. JS-тестов в проекте нет.
- **Окружение.** Python 3.14.1 на Windows. `fastapi` 0.142 и `httpx` 0.28 установлены, поэтому `fastapi.testclient.TestClient` доступен. `google-re2` пока не установлен в основном окружении. Его wheel 1.1.20251105 проверен во временном venv.
- **Импорт `api.py` безопасен.** `mcp_client` поднимает подпроцесс только в startup-хуке, а он не срабатывает, если `TestClient` используется без `with`.

Мотивация описана в proposal.md, раздел Why. Требования описаны в specs/domain-search/spec.md.

## Goals / Non-Goals

**Goals:**
- Логика сопоставления в одной чистой функции, полностью покрытой Python-тестами.
- Гарантированно линейное время сопоставления без таймаутов и потоков.
- Минимальная правка клиента: подстрочный поиск и пагинация не меняются.

**Non-Goals:**
- Серверная пагинация или серверный поиск подстроки.
- Автотесты JS-логики: клиент проверяется вручную, см. Risks.
- Совместимость синтаксиса с JS `RegExp`: используется синтаксис RE2.

## Decisions

### 1. Движок: `google-re2`

RE2 строит автомат без отката. Время линейно by design, обратные ссылки и lookaround не поддерживаются, и при компиляции такие выражения дают ошибку. Это совпадает с требованием отвечать 400.

Проверено:
- `re2.IGNORECASE` нет, регистр задаётся через `re2.Options()`, флаг `case_sensitive = False`;
- `log_errors = False` убирает шум absl в stderr (иначе он засоряет вывод тестов);
- сообщение ошибки лежит в `re2.error.args[0]` как `bytes`, его нужно декодировать в UTF-8;
- кириллица и регистр работают, `(a+)+$` на 100 000 символов отрабатывает примерно за 0.1 мс.

Отвергнутые альтернативы:
- **Stdlib `re`:** есть ReDoS и нет таймаута.
- **Библиотека `regex` с `timeout=`:** защищает только по времени, медленный запрос всё равно занимает воркер.
- **JS на клиенте:** безопасно для сервера, но не тестируется существующим runner.

### 2. Чистая функция `filter_domains(domains, pattern)` в `services.py`

```
filter_domains(domains: list[DomainItem], pattern: str) -> list[DomainItem]
    - len(pattern) > MAX_PATTERN_LENGTH (256)  -> InvalidPatternError
    - re2.compile(pattern, options)             -> re2.error -> InvalidPatternError(decoded msg)
    - [d for d in domains if compiled.search(d.domain)]
```

Решения по функции:
- **Своё исключение `InvalidPatternError(ValueError)`**, тоже в `services.py`. Так API не зависит от типов `re2`, а тесты проверяют контракт функции, а не библиотеку.
- **Лимит в 256 символов** взят как разумная граница. Реальные запросы по доменам короткие, а лимит отсекает тяжёлые для компиляции выражения. Если понадобится, его легко поменять в одной константе.
- **Пустой паттерн** обрабатывается на уровне API, функция его не получает.

### 3. API: параметр `regex` в `GET /api/domains`

`regex: str | None = None`:
- если значение пустое или `None`, ответ прежний;
- иначе вызывается `filter_domains(get_domains(), regex)`;
- `InvalidPatternError` превращается в `HTTPException(400, detail=f"Некорректное регулярное выражение: {msg}")`.

Формат элементов ответа (`d.dict()`) не меняется. В тестах патчится `api.get_domains`, потому что имя импортировано в модуль `api`.

### 4. Клиент: режимы и поток данных

```
 input / кнопка .*
        |
        v
 regexMode = manualRegex || /[\^$*+?()[\]{}|\\]/.test(query)
        |
   +----+-------------------------+
   | substring                    | regex
   | searchBase = allDomains,     | debounce 300 ms -> fetch /api/domains?regex=<encodeURIComponent>
   | фильтр includes(lower)       |   seq = ++requestSeq; ответ с seq != requestSeq игнорируется
   |                              |   200 -> regexResult = data, ошибка скрыта
   |                              |   400 -> regexResult не меняем, рамка + detail (textContent)
   +----+-------------------------+
        v
 applyFilters(): база (substring: allDomains | regex: regexResult ?? allDomains)
                 -> фильтр дат -> [includes, только в substring] -> пагинация
        v
 счётчик = filteredDomains.length
```

- **Состояние кнопки.** При спецсимволах в запросе кнопка `.*` подсвечена и её клик игнорируется. Без спецсимволов клик переключает `manualRegex`.
- **Регистр.** В regex-режиме запрос не приводится к нижнему регистру: `toLowerCase` сломал бы `\D`, `\W`, `\S`, `\B`. Регистр обрабатывает сервер. `trim()` остаётся: пробелов в доменах нет.
- **Пустой запрос** в regex-режиме, например кнопка нажата при пустом поле, не вызывает запрос. Показывается весь список.
- **Переход из regex в substring** сбрасывает ошибку, рамку и `regexResult = null`. Следующий заход в regex-режим начинается «с чистого листа»: до первого валидного ответа база — `allDomains`, а не результат прошлой regex-сессии. Без этого после `^a`, очистки поля и ввода `[` показался бы устаревший результат для `^a`. Ответы на запросы прошлой сессии, пришедшие после выхода, отбрасываются тем же счётчиком последовательности: выход из режима тоже увеличивает `requestSeq`.
- **Защита от гонок** сделана через счётчик последовательности. Он проще, чем `AbortController`, и достаточен: ответ на устаревший запрос просто отбрасывается.
- **Ошибка сети** (не 400) показывается тем же блоком ошибки с текстом «Ошибка загрузки».
- **Ошибка до первого валидного результата.** Пока `regexResult === null` (валидного regex-ответа ещё не было), ответ 400 не меняет базу: `applyFilters()` берёт `allDomains`. Пользователь видит полный список с учётом фильтра дат и ошибку под полем.
- **Вывод ошибки только через `textContent`.** `detail` содержит эхо пользовательского ввода: RE2 цитирует паттерн, например `missing ]: [a-`. Поэтому он MUST записываться в блок ошибки через `textContent`. Сборка строки и запись через `innerHTML` запрещены: иначе ввод `<img src=x onerror=…>(` превратится в разметку (self-XSS). Это же правило действует для сообщения о сетевой ошибке.

## Risks / Trade-offs

- **Клиентская логика не покрыта автотестами.** Runner только на Python, менять его нельзя. → Вся проверяемая логика (сопоставление, ошибки, регистр, кириллица, ReDoS) живёт на сервере. Клиент проверяется ручным сценарием в браузере по spec-сценариям UI. Детектор спецсимволов — одна регулярка, её проще проверить вручную.
- **Синтаксис RE2 отличается от привычного JS/PCRE:** нет `(?=`, `\1`. → Сервер возвращает 400 с текстом ошибки RE2, интерфейс показывает его под полем.
- **Эхо ввода в сообщении об ошибке.** → Вывод только через `textContent` (см. Decisions, п. 4). Ручная проверка вводом с HTML-фрагментом.
- **Сетевой запрос на ввод.** → Debounce 300 мс. Фильтрация работает по кешированному списку и линейна, поэтому нагрузка мала.
- **Широкое выражение вроде `.` возвращает весь список.** → Объём такой же, как у текущей загрузки `/api/domains`, это приемлемо.
- **Wheel `google-re2` может отсутствовать для другой платформы или версии Python.** → Для текущей среды wheel проверен. В `requirements.txt` указываем `google-re2>=1.1`.
- **Тест производительности может плавать на медленной машине.** → Порог 1 с при ожидаемых долях миллисекунды даёт большой запас.

## Migration Plan

1. `pip install -r requirements.txt` ставит `google-re2`.
2. Деплой не требует миграций данных. Клиенты без параметра `regex` работают как раньше.
3. Откат: отменить изменения. API без параметра полностью совместим.
