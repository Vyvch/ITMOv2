# Proposal

## Why

Сейчас поиск во вкладке «Все домены» ищет только подстроку (`includes` в `templates/index.html`). Поэтому нельзя искать по зоне (`ru` находит и `ruby.su`), по началу или концу имени, по шаблонам вида «только цифры». Регулярные выражения закрывают эти сценарии без отдельных фильтров. Если выполнять их на сервере безопасным движком, получим проверяемую на Python логику и не получим риска ReDoS.

## What Changes

- `GET /api/domains` получает необязательный query-параметр `regex`. Если он задан, сервер возвращает только домены, имя которых содержит совпадение с выражением. Без параметра ответ не меняется.
- Сопоставление идёт без учёта регистра, ищется совпадение в любом месте имени. Якоря `^` и `$` пользователь пишет сам. Кириллические имена (`.рф`) поддерживаются.
- Невалидное или неподдерживаемое выражение возвращает HTTP 400 с понятным сообщением. Неподдерживаемые: обратные ссылки, lookahead и lookbehind.
- Время сопоставления линейно растёт с длиной входа. «Катастрофические» паттерны вроде `(a+)+$` не подвешивают сервер.
- UI, вкладка «Все домены»:
  - кнопка `.*` рядом с полем поиска;
  - автоматическое включение regex-режима при наличии спецсимволов `^ $ * + ? ( ) [ ] { } | \`;
  - красная рамка и короткая ошибка под полем при невалидном выражении, при этом остаётся последний валидный результат;
  - счётчик найденных доменов.
- Обычный поиск по подстроке остаётся на клиенте без изменений, точка в нём буквальная.
- В `docs/requirements.md` добавляется «Фича C: Regex-поиск».
- Новая зависимость `google-re2` в `requirements.txt`.

Вне scope: CLI, отдельный фильтр по зонам, вкладки Топ-20, подсветка совпадений, состояние поиска в URL, поиск по punycode-форме (`xn--…`), переключатель регистра, кнопки-пресеты.

## Capabilities

### New Capabilities

- `domain-search`: поиск освобождающихся доменов по имени, по подстроке и по регулярному выражению. Покрывает поведение API (параметр, ошибки, регистр, производительность) и поведение поля поиска в веб-интерфейсе.

### Modified Capabilities

Нет: в `openspec/specs/` пока нет ни одной спеки.

## Impact

- **Код:**
  - `services.py`: новая чистая функция фильтрации;
  - `api.py`: параметр `regex` и ответ 400;
  - `templates/index.html`: кнопка, автоопределение, ошибка, счётчик, запросы к API.
- **API:** обратно совместимое расширение `GET /api/domains`.
- **Зависимости:** `google-re2`. Готовый wheel для Windows и Python 3.14 проверен.
- **Тесты:** новые тесты на Python в существующем runner `python scripts/check.py`. Сам runner не меняется.
- **Документация:** `docs/requirements.md`, Фича C.
