# Spec Delta

## Purpose

Позволяет находить освобождающиеся домены .ru, .su и .рф по имени: простым поиском подстроки или регулярным выражением. Поиск безопасен для сервера при любых выражениях.

## ADDED Requirements

### Requirement: Фильтрация списка доменов по регулярному выражению
`GET /api/domains` SHALL принимать необязательный query-параметр `regex`. Если параметр задан и не пуст, ответ MUST содержать только те домены, в имени которых есть хотя бы одно совпадение с выражением в любой позиции. Формат элементов ответа MUST остаться прежним.

#### Scenario: Выражение с якорем по зоне
- **WHEN** клиент запрашивает `GET /api/domains?regex=\.su$`, а в списке есть `alpha.su`, `beta.ru` и `su-shop.ru`
- **THEN** ответ имеет статус 200 и содержит только `alpha.su`

#### Scenario: Совпадение в середине имени
- **WHEN** клиент запрашивает `GET /api/domains?regex=[0-9]{3}`, а в списке есть `shop123.ru` и `shop.ru`
- **THEN** ответ содержит `shop123.ru` и не содержит `shop.ru`

#### Scenario: Нет совпадений
- **WHEN** выражение валидно, но ни одно имя ему не соответствует
- **THEN** ответ имеет статус 200 и содержит пустой список

### Requirement: Обратная совместимость без параметра
Если параметр `regex` отсутствует или пуст, `GET /api/domains` MUST возвращать полный список доменов, как до изменения.

#### Scenario: Запрос без параметра
- **WHEN** клиент запрашивает `GET /api/domains`
- **THEN** ответ содержит все домены из источника

#### Scenario: Пустой параметр
- **WHEN** клиент запрашивает `GET /api/domains?regex=`
- **THEN** ответ содержит все домены из источника

### Requirement: Регистр не учитывается
Сопоставление с регулярным выражением MUST выполняться без учёта регистра, в том числе для кириллицы.

#### Scenario: Латиница в верхнем регистре
- **WHEN** клиент запрашивает `GET /api/domains?regex=^SHOP`, а в списке есть `shop.ru`
- **THEN** ответ содержит `shop.ru`

#### Scenario: Кириллица в верхнем регистре
- **WHEN** клиент запрашивает `GET /api/domains?regex=^ПРИМЕР`, а в списке есть `пример.рф`
- **THEN** ответ содержит `пример.рф`

### Requirement: Поиск по кириллическим доменам
Выражения MUST сопоставляться с именами `.рф` в их кириллической форме, в которой они показываются пользователю.

#### Scenario: Поиск по зоне .рф
- **WHEN** клиент запрашивает `GET /api/domains?regex=\.рф$`, а в списке есть `пример.рф` и `example.ru`
- **THEN** ответ содержит только `пример.рф`

### Requirement: Ошибка для невалидного или неподдерживаемого выражения
Если выражение синтаксически невалидно, использует неподдерживаемые конструкции (обратные ссылки, lookahead, lookbehind) или длиннее 256 символов, сервер MUST ответить HTTP 400. Тело ответа MUST содержать поле `detail` с читаемым сообщением о причине.

#### Scenario: Незакрытая скобка
- **WHEN** клиент запрашивает `GET /api/domains?regex=[a-`
- **THEN** ответ имеет статус 400, а `detail` содержит сообщение об ошибке в выражении

#### Scenario: Обратная ссылка
- **WHEN** клиент запрашивает `GET /api/domains?regex=(a)\1`
- **THEN** ответ имеет статус 400

#### Scenario: Lookahead
- **WHEN** клиент запрашивает `GET /api/domains?regex=a(?=b)`
- **THEN** ответ имеет статус 400

#### Scenario: Слишком длинное выражение
- **WHEN** клиент передаёт выражение длиной 257 символов
- **THEN** ответ имеет статус 400

### Requirement: Защита от катастрофического перебора
Время сопоставления MUST расти линейно с длиной входа при любом допустимом выражении. Выражения, которые в движках с откатом дают экспоненциальное время, MUST обрабатываться быстро.

#### Scenario: Паттерн (a+)+$ на длинной строке
- **WHEN** выражение `(a+)+$` применяется к списку, где есть имя из 50 000 символов `a` и `!` в конце
- **THEN** фильтрация завершается менее чем за 1 секунду и не включает это имя в результат

### Requirement: Включение regex-режима в веб-интерфейсе
Во вкладке «Все домены» рядом с полем поиска MUST быть кнопка `.*`. Regex-режим MUST быть активен, если кнопка нажата пользователем или если запрос содержит хотя бы один из символов `^ $ * + ? ( ) [ ] { } | \`. В остальных случаях MUST использоваться поиск подстроки, в котором точка буквальная.

#### Scenario: Автовключение по спецсимволу
- **WHEN** пользователь вводит `^abc`, не нажимая кнопку
- **THEN** включается regex-режим, кнопка `.*` подсвечена как активная

#### Scenario: Кнопку нельзя выключить при спецсимволах
- **WHEN** запрос содержит `$`, и пользователь нажимает активную кнопку `.*`
- **THEN** regex-режим остаётся включён

#### Scenario: Ручное включение для точки
- **WHEN** пользователь нажимает `.*` и вводит `a.c`
- **THEN** выполняется regex-поиск, в результат попадает и `abc.ru`

#### Scenario: Обычный поиск с точкой
- **WHEN** кнопка не нажата, и пользователь вводит `a.c`
- **THEN** выполняется поиск подстроки `a.c`, `abc.ru` в результат не попадает

#### Scenario: Возврат к подстроке
- **WHEN** пользователь стирает все спецсимволы из запроса, а кнопку вручную не нажимал
- **THEN** кнопка гаснет и применяется поиск подстроки

### Requirement: Отображение ошибки выражения
Если сервер отклонил выражение, интерфейс MUST показать красную рамку у поля и короткое сообщение об ошибке под ним. Список MUST остаться последним валидным regex-результатом. Если такого ещё не было, MUST показываться полный список с учётом фильтра дат. Сообщение MUST выводиться как текст, без интерпретации HTML. Когда выражение снова становится валидным, ошибка MUST исчезнуть.

#### Scenario: Ввод невалидного выражения
- **WHEN** в regex-режиме пользователь вводит `[a-`
- **THEN** поле получает красную рамку, под ним появляется сообщение об ошибке, список доменов не меняется

#### Scenario: Ошибка до первого валидного результата
- **WHEN** выбран фильтр «Завтра», и первым символом в поле введён `[`, на который сервер отвечает 400
- **THEN** поле получает красную рамку и сообщение об ошибке, а показывается полный список доменов, освобождающихся завтра

#### Scenario: HTML в сообщении об ошибке не интерпретируется
- **WHEN** пользователь вводит невалидное выражение, содержащее `<img src=x onerror=alert(1)>(`
- **THEN** сообщение об ошибке показывает этот фрагмент как обычный текст, разметка не создаётся и скрипт не выполняется

#### Scenario: Исправление выражения
- **WHEN** после ошибки пользователь дописывает `[a-z]`
- **THEN** рамка и сообщение исчезают, список обновляется по новому выражению

### Requirement: Счётчик найденных доменов
Рядом с полем поиска MUST отображаться число доменов, найденных с учётом всех активных фильтров: дат и поиска.

#### Scenario: Обновление счётчика
- **WHEN** пользователь меняет запрос или фильтр дат
- **THEN** счётчик показывает число доменов в текущем отфильтрованном списке

### Requirement: Комбинация regex с фильтрами дат и пагинацией
Результат regex-поиска MUST дополнительно фильтроваться активными фильтрами дат и разбиваться на страницы так же, как результат поиска подстроки.

#### Scenario: Regex и фильтр «Завтра»
- **WHEN** выбран фильтр «Завтра» и введено `\.ru$`
- **THEN** показываются только домены `.ru`, освобождающиеся завтра, по 100 на страницу
