# Research: История домена в веб-архиве (интерфейс)

**Фича**: `specs/001-wayback-ui/spec.md` | **Контракт**: `specs/wayback-contract.md` v1.2 | **Дата**: 2026-10-28

Неизвестных в Technical Context не осталось; ниже — решения, принятые при их разборе.

## R1. Как тестировать логику интерфейса по TDD без npm

- **Decision**: вся логика без DOM (разбор ответа, форматирование, таймеры, повторы, отмена) живёт
  в отдельном блоке `<script id="wayback-core">` внутри `templates/index.html` и публикует объект
  `WaybackCore` в `globalThis`. Тест `tests/test_wayback_ui.py` (unittest) извлекает текст блока
  из HTML и выполняет его в `node` через встроенный модуль `vm` с подменёнными `fetch`, часами
  и таймерами; результат сценария возвращается в Python как JSON и проверяется `assert*`.
  В новом контексте `vm` есть только встроенные объекты JS, поэтому обвязка явно передаёт в песочницу
  веб-API, которые ядро берёт из глобальной области: `URL`, `AbortController`, `console`. Сценарии
  асинхронные: обвязка оборачивает их в `async`-функцию, ждёт её завершения и только потом печатает JSON.
  Если `node` нет в `PATH`, эти тесты пропускаются (`skipTest`) с явной причиной; критерий готовности
  (T028) требует 0 пропущенных тестов.
- **Rationale**: принцип I запрещает сборщики и npm, но не запрещает запуск JS-движка в тестах;
  Node 24 уже установлен, `vm` встроен. Runner `scripts/check.py` и `unittest` не меняются
  (принципы II и III). Один файл `index.html` остаётся единственным источником кода UI.
- **Alternatives considered**:
  - `py_mini_racer`/`quickjs` — новая Python-зависимость, нет уверенности в колёсах под 3.14.
  - Playwright/Selenium — тяжёлые зависимости и загрузка браузера ради нескольких сценариев.
  - Только статические проверки HTML — не покрывают машину состояний (202, таймауты, отсчёт).
  - Отдельный `.js`-файл в `static/` — нарушает «один templates/index.html».

## R2. Статические проверки безопасности и границ (всегда без node)

- **Decision**: `tests/test_wayback_ui.py` также содержит Python-тесты по тексту `index.html`:
  1. `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write` не используются, кроме
     очистки `innerHTML = ''` (принцип V, FR-020…FR-022);
  2. `fetch(` вызывается только с относительными адресами `/api/...` (принцип IV), и каждый
     подставляемый параметр запроса обёрнут в `encodeURIComponent` (принцип V); это требует исправить
     существующий `fetch(\`/api/top?date_type=${dateType}\`)` в `loadTop`;
  3. присутствуют элементы-якоря интерфейса из `contracts/ui-contract.md`.
- **Rationale**: дешёвый страховочный слой, который работает и без node и ловит регрессии
  при будущих правках.
- **Alternatives considered**: CSP-заголовок `script-src` — полезен, но меняет сервер (не наша зона)
  и не заменяет проверку кода; отложено.

## R3. Карточка домена во вкладке «Все домены»

- **Decision**: нативный `<dialog id="domain-dialog">`, открывается `showModal()`. Карточки сетки
  становятся элементами `<button type="button" class="domain-card">` (вид сохраняется CSS-сбросом).
- **Rationale**: Esc, фокус внутри окна, затемнение фона и блокировка списка (FR-001, FR-003,
  пограничный случай «пагинация недоступна при открытой карточке») — из коробки. `<button>` даёт
  Enter/Space и фокус без своего кода. Клик вне карточки — проверка `event.target === dialog`.
- **Alternatives considered**: свой `div`-оверлей — нужно вручную ловить фокус и Esc;
  раскрытие карточки на месте в сетке — ломает раскладку сетки и пагинацию.

## R4. Машина состояний блока истории

- **Decision**: `WaybackCore.createHistoryLoader(domain, deps)` возвращает `{ start(), cancel() }`
  и сообщает состояния через `deps.onState(state)`. Внутри:
  - дедлайн попытки — 120 000 мс от `start()` (FR-013); по дедлайну → `timeout`, даже если ждёт
    повтор 202 или идёт запрос;
  - таймаут одного запроса — 20 000 мс через `AbortController` (контракт, правило 12) → `timeout`;
  - `202` → остаётся `loading`, повтор через `retry_after` с (тело, иначе заголовок, минимум 1 с);
    если повтор позже дедлайна — не планируется, срабатывает дедлайн;
  - `cancel()` прерывает запрос, снимает все таймеры и увеличивает «поколение»; любой ответ
    старого поколения игнорируется (FR-014, пограничные случаи с закрытием карточки);
  - `start()` после итогового состояния — новая попытка с новым дедлайном (сценарий 11 US2);
  - слот ограничителя (R9) занимается только на время одного запроса и освобождается сразу после
    ответа или таймаута; ожидание повтора после `202` слот не держит, повтор занимает его заново.
- **Decision (отсчёт)**: обратный отсчёт «Повторить через N с» — тоже в ядре:
  `WaybackCore.createCountdown(seconds, deps, onTick)` вызывает `onTick(N)` сразу и затем раз в 1000 мс
  до `onTick(0)`, возвращает `{ cancel() }`; DOM-код только показывает число. Так FR-012b проверяется
  тестом на виртуальных часах.
- **Decision (закрытие)**: отмена загрузки и отсчёта привязана к событию `close` элемента `dialog`,
  которое срабатывает при любом способе закрытия — кнопка, Esc, клик по фону.
- **Rationale**: одно место для всех правил времени; зависимости (`fetch`, `now`, `setTimeout`,
  `clearTimeout`) внедряются — тесты в node крутят виртуальные часы без реального ожидания.
- **Alternatives considered**: `Promise.race` с `setTimeout` на каждый вызов — сложно отменять
  цепочку повторов; общий глобальный таймер для всех карточек — ломает независимость (FR-019).

## R5. Разбор ответа сервера

- **Decision**: чистая функция `WaybackCore.classifyResponse(status, retryAfterHeader, bodyText)`
  возвращает одно из: `success`, `empty`, `pending`, `overloaded`, `timeout`, `failed`, `invalid`
  (+ данные). Правила — по контракту: ветвление по HTTP-статусу, для ошибок — по `code`; `detail`
  не читается (FR-012). Невалидный JSON, неизвестный статус/код, `200` без числового
  `snapshot_count` → `failed`. `invalid_domain` → `invalid` (тот же текст, без «Повторить», FR-012c).
- **Rationale**: таблица «вход → состояние» напрямую превращается в табличный тест.
- **Alternatives considered**: ветвление по `detail` — запрещено контрактом (правило 2).

## R6. Форматирование

- **Decision**:
  - дата: `/^(\d{4})-(\d{2})-(\d{2})$/` → `ДД.ММ.ГГГГ` перестановкой, без `Date` (FR-009a);
    иначе `—`;
  - число: `Intl.NumberFormat('ru-RU')` от `count`; при `count_truncated` к нему добавляется `+`
    (по контракту `count = 100000` → `100 000+`). Разделитель разрядов — неразрывный пробел U+00A0,
    чтобы число не переносилось;
  - отсутствующие `first`/`last` при ненулевом числе → `—` без ссылки.
- **Rationale**: перестановка исключает сдвиг даты часовым поясом браузера (контракт, правило 9).
- **Alternatives considered**: `new Date(date).toLocaleDateString()` — сдвигает дату к западу от UTC.

## R7. Ссылки

- **Decision**:
  - «Открыть в веб-архиве»: `https://web.archive.org/web/*/` + ASCII-форма хоста, полученная
    через `new URL('http://' + domain).hostname` (для `.рф` — punycode, встроено в браузер).
    Атрибуты `target="_blank" rel="noopener noreferrer"` (FR-005).
  - Ссылки на снимки: `new URL(url)`, принимаются только `protocol === 'https:'` и
    `hostname === 'web.archive.org'` (FR-010); иначе — только дата. Это строже правила 10 контракта
    и совпадает с его гарантией для `first.url`/`last.url`. Адрес ставится через свойство `href`,
    текст — через `textContent`.
- **Rationale**: punycode однозначно адресует домен в архиве и не зависит от того, как архив
  разбирает процентное кодирование кириллицы; спецификация требует «страницу снимков именно этого
  домена», а не кириллицу в адресной строке.
- **Alternatives considered**: `encodeURIComponent(domain)` — адрес вида `%D0%BF...`; архив
  обычно его понимает, но поведение не гарантировано, отклонено.

## R8. Запоминание результатов в сессии страницы

- **Decision**: общий `Map` «домен в нижнем регистре → результат» для `success`/`empty`, одна
  копия на страницу; используется и карточкой домена, и Топ-20 (FR-015). Ошибки и `pending`
  не кладутся.
- **Rationale**: повторное открытие карточки мгновенно; домен, историю которого уже запросили
  в карточке или в Топ-20, при новой отрисовке Топ-20 сразу показывает результат без кнопки и запроса.
- **Alternatives considered**: `localStorage` — переживает перезагрузку, что противоречит FR-015.

## R9. История в Топ-20 — по нажатию; параллельные запросы

- **Decision**: в Топ-20 история НЕ загружается автоматически (FR-018): у каждой строки блок
  в состоянии `idle` с кнопкой «Запросить историю» (или запомненный результат из R8), запрос —
  только по нажатию. Ограничитель параллельности в `WaybackCore` сохраняется: не более 4
  одновременных запросов истории на страницу (FR-019a); остальные ждут очереди в `loading`.
  Дедлайн 2 минуты считается с нажатия (включая ожидание очереди), таймаут 20 с — с фактической
  отправки. Слот освобождается после каждого ответа: домен, ждущий повтора после `202`, не блокирует
  остальные. Загрузчики строк Топ-20 хранятся в списке и отменяются при смене списка.
- **Rationale**:
  - автозагрузка отклонена по замерам сервера (контракт 1.2): холодный запрос к архиву ~17 с,
    обращения к архиву идут по одному, поэтому 20 доменов — 40–60 с и больше, плюс нагрузка на
    архив за домены, которые пользователь может не смотреть;
  - ограничитель всё ещё нужен: пользователь может быстро нажать кнопку в 7+ строках. Браузер
    держит ~6 соединений HTTP/1.1 на хост, а сервер держит ответ до 15 с, поэтому седьмой запрос
    стоял бы в очереди браузера, и 20-секундный таймаут от вызова `fetch` срабатывал бы ложно.
    4 слота оставляют соединения для `/api/top` и `/api/domains`;
  - отмена при смене списка всё ещё нужна: без неё повторы после `202` и отсчёты исчезнувших
    строк продолжались бы до 2 минут и слали бы лишние запросы.
- **Alternatives considered**: автозагрузка с ограничителем — слишком долго (см. выше); загрузка
  только первых N строк — неочевидно для пользователя; без ограничителя — ложные таймауты при
  частых нажатиях; без отмены при смене списка — фоновые запросы за невидимые строки.

## R10. Безопасный рендер Топ-20

- **Decision**: строки Топ-20 собираются хелпером `el(tag, props, children)` на `createElement`
  и `textContent`; ветки WHOIS (свободен / ошибка / поля / сырой JSON в `<pre>`) сохраняются как
  есть, жирные подписи — отдельными `<strong>`, переносы — `<br>`-элементами. Сетка «Все домены»
  переводится так же (FR-022). Добавляется колонка «Веб-архив».
- **Rationale**: принцип V и FR-021 (внешний вид как прежде).
- **Alternatives considered**: экранирующая функция + `innerHTML` — запрещено принципом V.

## R11. Доступность

- **Decision**: блок истории — `role="status"` (`aria-live="polite"`) (FR-016); у диалога
  `aria-labelledby` на заголовок с именем домена; кнопка с отсчётом — `disabled` и текст
  «Повторить через N с», обновляется раз в секунду.
- **Rationale**: стандартные средства без библиотек.
