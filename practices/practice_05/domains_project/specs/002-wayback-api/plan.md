# Implementation Plan: История домена в веб-архиве (сервер)

**Branch**: `002-wayback-api` | **Date**: 2026-10-28 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/002-wayback-api/spec.md`; общий контракт
`specs/wayback-contract.md` (приоритетен при расхождениях).

## Summary

Новый эндпоинт `GET /api/wayback?domain=<домен>` отдаёт историю главной страницы домена в веб-архиве:
число снимков, первый и последний снимок (UTC-дата + адрес снимка). Данные берутся одним запросом
к Wayback CDX (`fl=timestamp,original`, до 100 000 строк). Все обращения к архиву идут через
единственного асинхронного «работника» очереди: не чаще 1 раза в секунду, объединение одинаковых
доменов, пауза с удвоением после «429». Клиент ждёт результат не дольше 15 с, иначе получает
`202 pending` с `retry_after`; задача дорабатывается в фоне. Успехи и «нет снимков» кэшируются на 7 дней
в памяти с сохранением в JSON-файл. Ошибки — доменные исключения с `code`, которые эндпоинт превращает
в ответы `400/502/503/504` по контракту. Объекты `asyncio` не создаются при импорте — только лениво внутри работающего цикла,
со сбросом при смене цикла и между тестами (R10). Подробности решений — [research.md](research.md).

## Technical Context

**Language/Version**: Python 3.14 (установлен 3.14.1)

**Primary Dependencies**: FastAPI (через `fastapi[standard]`), `httpx` (уже используется в
`services.py`, приходит с `fastapi[standard]`), Pydantic v2. Новых зависимостей нет.

**Storage**: кэш в памяти процесса + JSON-файл `.cache/wayback_cache.json` (путь переопределяется
переменной окружения `WAYBACK_CACHE_PATH`); атомарная запись через временный файл и `os.replace`.

**Testing**: `unittest` (`IsolatedAsyncioTestCase` для очереди), `fastapi.testclient.TestClient`
для эндпоинта; архив, часы и файл кэша подменяются; запуск — `python scripts/check.py`.

**Target Platform**: локальный сервер `uvicorn`/`fastapi dev`, один процесс, Windows/Linux.

**Project Type**: web-service (FastAPI-мини-сайт с CLI), плоская структура модулей в корне проекта.

**Performance Goals**: ответ из кэша < 0,1 с; ≤ 1 обращения к архиву в секунду; 20 холодных доменов
Топ-20 оказываются в кэше ≤ 1 мин при ответах архива < 2 с (SC-006).

**Constraints**: ответ клиенту ≤ 15 с; таймаут обращения к архиву 10 с (общий, не на чтение
фрагмента); очередь ≤ 100 задач; кэш ≤ 10 000 записей; пауза после «429» 60 с → ×2 → ≤ 600 с.

**Scale/Scope**: один пользователь/вкладка, до ~20 одновременных запросов (Топ-20); ~6 новых
публичных функций/классов, 2 новых тестовых модуля.

**Structure Decision**: сохраняем плоскую структуру проекта (модули в корне, как `mcp_client.py`).
Вся логика фичи — в отдельном `wayback.py`; `api.py` только валидирует вход и переводит результат
и исключения в HTTP-ответы; `services.py` реэкспортирует точку входа, чтобы CLI в будущем брал
логику оттуда же, откуда и веб.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| Логика в новом модуле `wayback.py`, а не прямо в `services.py` | ~300 строк с собственным состоянием (очередь, работник, кэш, пауза) и отдельными тестами; `services.py` реэкспортирует `get_wayback_history`, так что требование «общая логика из `services.py`» для API и CLI выполняется | Вставка в `services.py` удвоит файл и смешает загрузку списка доменов, LLM и очередь архива в одном модуле с глобальным состоянием |
| Асинхронный работник очереди в синхронном в остальном API | Ожидание до 15 с с объединением запросов, фоновой доработкой и паузой естественно выражается `asyncio`-задачей и `Future`; эндпоинт `async def` не блокирует пул потоков на время ожидания | Потоки + `threading.Condition`: 20 ожидающих запросов заняли бы 20 потоков пула, а таймауты и отмена сложнее тестировать |

## Риски

| # | Риск | Последствие | Снижение | Проверка |
|---|------|-------------|----------|----------|
| R-1 | `TestClient` и `IsolatedAsyncioTestCase` запускают новый цикл событий на тест или запрос, а очередь держит объекты `asyncio` (событие, работник, `Future`) | `RuntimeError: ... attached to a different loop` или зависший тест | Ничего `asyncio` при импорте; `_ensure_runtime()` создаёт объекты лениво в работающем цикле и сбрасывает состояние выполнения при смене цикла; `httpx.AsyncClient` — на каждое обращение (R10) | Сквозной тест: два запроса через `TestClient` без `with` подряд, оба отвечают, второй — из кэша |
| R-2 | Модульный сервис переносит состояние (очередь, паузу, кэш) из одного теста в другой | Тесты зависят от порядка и «мигают» | `reset_service()` в `setUp`/`tearDown`; тесты сервиса создают свой экземпляр; кэш-файл — во временном каталоге | Полный прогон `python scripts/check.py` и прогон модулей в обратном порядке дают одинаковый результат |
| R-3 | Реальный формат CDX (строка, пустой ответ, исключённый сайт) расходится с допущениями R1–R2 | Разборщик проходит тесты, но ломается на настоящем архиве | Первая задача — снять реальные ответы и сохранить образцы в `tests/fixtures/wayback/` до написания разборщика | Тесты разбора используют образцы; ручные сценарии M1, M4 из quickstart |
| R-4 | Архив режет запросы чаще, чем 1/с | Длинные серии «429», пауза до 10 мин | Интервал вынесен в настройку; удвоение паузы с пределом | Журнал «429» при ручной проверке M6 |
| R-5 | Ошибка в работнике «убивает» задачу-работника | Очередь перестаёт обслуживаться до перезапуска | Работник ловит все исключения на уровне задачи и превращает их в `ArchiveUnavailable` (FR-026); `_ensure_runtime()` перезапускает завершившегося работника | Тест: фейковый загрузчик бросает `RuntimeError`, следующий запрос обслуживается |

## Указания для `/speckit-tasks`

- **Первая задача (T001)**: один раз вручную снять реальные ответы Wayback CDX тем же запросом,

  и регрессионный тест смены цикла (R-1) — в фундаментальной фазе, до очереди и эндпоинта.
