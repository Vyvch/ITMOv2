# Feature Specification: История домена в веб-архиве (сервер)

**Feature Branch**: `002-wayback-api`

**Created**: 2026-10-28

**Status**: Draft

**Input**: User description: "Фича wayback-api (короткое имя: wayback-api). Это спецификация ТОЛЬКО
серверной логики — интерфейс проектирует другая команда. Сервер получает историю домена из Wayback
CDX API: число снимков, первый и последний снимок (дата + ссылка). Кэш результатов (~7 дней), запросы
к архиву очередью с паузами (у архива лимиты), обработка 429, таймаута и «нет снимков». Опиши данные,
алгоритм, правила и API-эндпоинт."

**Граница фичи**: описывается только серверная часть — получение истории из веб-архива, кэш, очередь
запросов, обработка ошибок и собственный эндпоинт сайта. Экраны, карточки и состояния интерфейса
описаны в спецификации `specs/001-wayback-ui/spec.md` (другая команда); её раздел «Ожидания от
сервера» (EXP-001…EXP-006) — входные требования к этой фиче.

**Связь с контрактом**: в `docs/requirements.md` раздела про веб-архив нет; фича опирается на
принцип IV конституции («Внешние сервисы только через сервер»: таймаут, конкретные ошибки, кэш
с TTL). Контракт этой спецификацией не меняется.

**Потребитель**: «пользователь» в сценариях ниже — клиент собственного API сайта (интерфейс сайта,
тесты, разработчик с `curl`). Конечный посетитель сайта видит результат через интерфейс 001-wayback-ui.

**Общий контракт**: формат эндпоинта, согласованный с командой интерфейса, вынесен в
`specs/wayback-contract.md`. При расхождении этой спецификации с ним приоритет у файла контракта.

## Clarifications

### Session 2026-10-28

- Q: Что отвечает сервер, если домен стоит в очереди сервера и результат не готов за 15 с? → A: HTTP 202
  `{"domain": ..., "status": "pending", "retry_after": N}` и заголовок `Retry-After: N`; задача остаётся
  в очереди. HTTP 503 `archive_overloaded` — только при настоящей перегрузке: «429» от архива, пауза
  после «429», переполненная очередь.
- Q: Какое поле ответа об ошибке клиент использует как признак ошибки? → A: `code` — основной
  машинный признак; `detail` — только человекочитаемое описание, клиент не разбирает его текст.
- Q: В каком часовом поясе и формате поле `date` снимка? → A: дата снимка в UTC в формате
  `ГГГГ-ММ-ДД`; клиент показывает её без пересчёта часовых поясов.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Получить историю домена в веб-архиве (Priority: P1)

Клиент запрашивает у сервера историю одного домена из зон `.ru`, `.su`, `.рф`. Сервер обращается
к индексу снимков веб-архива и возвращает: сколько раз архив сохранял главную страницу домена,
когда и по какому адресу сохранён первый снимок и когда и по какому адресу — последний. Если
архив домен никогда не сохранял, сервер отвечает обычным (не ошибочным) результатом с нулём снимков.

**Why this priority**: это вся полезная нагрузка фичи; без неё интерфейсу нечего показывать.

**Independent Test**: подставить вместо архива заглушку, возвращающую заданный список снимков
(и пустой список), вызвать эндпоинт и сверить число, даты и адреса первого и последнего снимка.

**Acceptance Scenarios**:

1. **Given** архив хранит 1 234 снимка главной страницы `example.ru`, самый ранний — 15.03.2009
   12:34:56 UTC, самый поздний — 02.10.2026 08:00:00 UTC, **When** клиент запрашивает историю
   `example.ru`, **Then** сервер отвечает успехом: `snapshot_count = 1234`, первый снимок с датой
   `2009-03-15` и адресом `https://web.archive.org/web/20090315123456/<исходный адрес>`, последний —
   с датой `2026-10-02` и адресом `https://web.archive.org/web/20261002080000/<исходный адрес>`.
2. **Given** архив не хранит ни одного снимка `never-archived.ru`, **When** клиент запрашивает его
   историю, **Then** сервер отвечает успехом с `snapshot_count = 0`, а первый и последний снимок
   отсутствуют (`null`).
3. **Given** у домена ровно один снимок, **When** клиент запрашивает историю, **Then** первый
   и последний снимок совпадают, `snapshot_count = 1`.
4. **Given** клиент передал `пример.рф` в кириллице, **When** сервер обращается к архиву, **Then**
   поиск идёт по форме домена, в которой архив его индексирует (punycode `xn--e1afmkfd.xn--p1ai`),
   а в ответе поле `domain` возвращается в той же кириллической форме, в какой пришло.
5. **Given** клиент передал `Example.RU` или `example.ru.` (с точкой в конце), **When** сервер
   обрабатывает запрос, **Then** домен нормализуется до `example.ru` и ответ совпадает с ответом
   на `example.ru`.
6. **Given** клиент передал пустое значение, адрес со схемой или путём (`http://example.ru/page`),
   домен другой зоны (`example.com`) или строку с недопустимыми символами, **When** сервер
   проверяет запрос, **Then** он отвечает ошибкой «некорректный домен» (HTTP 400) и не обращается
   к архиву.

### User Story 2 - Понятные ошибки при сбоях архива (Priority: P2)

Веб-архив бывает перегружен (отвечает «слишком много запросов»), отвечает слишком долго или
возвращает неожиданный ответ. Клиент получает не «внутреннюю ошибку сервера», а одну из трёх
различимых ошибок с человекочитаемым описанием: «архив перегружен», «таймаут архива», «ошибка
архива» — чтобы интерфейс показал правильное сообщение и кнопку «Повторить».

**Why this priority**: без этого любой сбой внешнего сервиса превращается в 500 со стектрейсом,
что прямо запрещено принципом IV конституции; интерфейс 001-wayback-ui опирается на различимость
ошибок (EXP-003).

**Independent Test**: заглушка архива поочерёдно отвечает «429», не отвечает дольше таймаута,
отвечает 500 и отдаёт мусор вместо списка снимков; для каждого случая проверяется код ответа,
код ошибки и наличие описания.

**Acceptance Scenarios**:

1. **Given** архив отвечает на запрос «429 Too Many Requests», **When** клиент запрашивает историю,
   **Then** сервер отвечает HTTP 503 с кодом `archive_overloaded`, описанием «Веб-архив перегружен,
   попробуйте позже» и заголовком `Retry-After`.
2. **Given** архив не ответил за 10 секунд, **When** клиент запрашивает историю, **Then** сервер
   отвечает HTTP 504 с кодом `archive_timeout` и описанием «Веб-архив не ответил вовремя».
3. **Given** архив недоступен по сети, ответил кодом 5xx или вернул ответ, который нельзя разобрать
   как список снимков, **When** клиент запрашивает историю, **Then** сервер отвечает HTTP 502
   с кодом `archive_error` и описанием «Не удалось получить историю из веб-архива».
4. **Given** произошла любая из ошибок выше, **When** сервер сформировал ответ, **Then** ошибка
   записана в журнал сервера (домен, тип ошибки, длительность), а в ответе нет стектрейса
   и внутренних подробностей.
5. **Given** ранее запрос истории `example.ru` завершился ошибкой, **When** клиент повторяет
   запрос, **Then** сервер снова обращается к архиву (ошибки не кэшируются).

### User Story 3 - Кэш истории на 7 дней (Priority: P3)

Повторный запрос истории того же домена в течение 7 дней обслуживается из кэша сервера мгновенно
и без обращения к архиву. Кэш переживает перезапуск сервера.

**Why this priority**: история домена меняется медленно, а лимиты архива жёсткие; кэш снимает
нагрузку с архива при повторных открытиях карточек и вкладки Топ-20 (EXP-005).

**Independent Test**: запросить историю домена дважды с подсчётом обращений к заглушке архива;
сдвинуть «текущее время» на 7 дней + 1 секунду и запросить снова.

**Acceptance Scenarios**:

1. **Given** история `example.ru` получена 1 час назад, **When** клиент запрашивает её снова,
   **Then** сервер отвечает тем же результатом без обращения к архиву, `cached = true`, а `checked_at`
   — время исходного получения.
2. **Given** результат «0 снимков» получен 2 дня назад, **When** клиент запрашивает историю снова,
   **Then** сервер отвечает из кэша (результат «нет снимков» кэшируется наравне с успехом).
3. **Given** история получена 7 дней и 1 секунду назад, **When** клиент запрашивает её, **Then**
   запись считается устаревшей и сервер обращается к архиву заново.
4. **Given** история `пример.рф` получена по кириллическому имени, **When** клиент запрашивает
   `xn--e1afmkfd.xn--p1ai`, **Then** ответ берётся из той же записи кэша (ключ — нормализованный домен).
5. **Given** в кэше есть свежие записи, **When** сервер перезапускается, **Then** после запуска
   эти записи по-прежнему обслуживаются без обращения к архиву.

### User Story 4 - Очередь запросов к архиву с паузами (Priority: P4)

Когда за историей приходит много клиентов сразу (вкладка Топ-20 запрашивает 20 доменов), сервер
не обрушивает их на архив, а пропускает через единую очередь: не чаще одного обращения в секунду,
одинаковые одновременные запросы объединяются в одно обращение, а после ответа «429» очередь
выдерживает паузу. Если результат не готов за 15 секунд, клиент получает ответ «в очереди»
(HTTP 202) с подсказкой, через сколько секунд повторить, а сервер дорабатывает запрос в фоне
и кладёт результат в кэш — повтор будет мгновенным. Ответ «архив перегружен» (HTTP 503)
означает только настоящую перегрузку: «429» от архива, паузу после него или переполненную очередь.

**Why this priority**: защищает от блокировки сервера архивом; на малой нагрузке фича работает
и без очереди, поэтому приоритет ниже кэша.

**Independent Test**: отправить 20 одновременных запросов разных доменов при заглушке архива
с задержкой ответа 1 с; проверить моменты обращений к заглушке, время каждого ответа сервера
и то, что повторный запрос после `Retry-After` отдаётся из кэша.

**Acceptance Scenarios**:

1. **Given** очередь пуста, **When** одновременно пришли 20 запросов разных доменов, которых нет
   в кэше, **Then** обращения к архиву идут строго по одному с интервалом между началами
   обращений не менее 1 секунды.
2. **Given** запрос истории `example.ru` уже ждёт в очереди или выполняется, **When** приходит ещё
   5 запросов `example.ru`, **Then** к архиву уходит одно обращение, и все 6 клиентов получают
   один и тот же результат.
3. **Given** домен `example.ru` поставлен в очередь, паузы после «429» нет, **When** результат
   не готов через 15 секунд от получения запроса (или оценка ожидания заранее превышает 15 секунд),
   **Then** сервер отвечает HTTP 202 с телом `{"domain": "example.ru", "status": "pending",
   "retry_after": N}` и заголовком `Retry-After: N` (N — оценка в целых секундах, через сколько
   результат будет готов, не меньше 1), а задача остаётся в очереди и после выполнения попадает
   в кэш.
4. **Given** клиент получил 202 для `example.ru`, **When** он повторяет запрос через `retry_after`
   секунд и задача уже выполнена успешно, **Then** сервер отвечает HTTP 200 из кэша; если задача
   ещё в очереди — запрос присоединяется к ней (без нового обращения к архиву) и снова ждёт до
   15 секунд.
5. **Given** архив ответил «429», **When** очередь продолжает работу, **Then** она приостанавливает
   все обращения к архиву на время паузы (значение `Retry-After` архива, если он его прислал,
   иначе 60 с; при повторных «429» подряд пауза удваивается до 10 минут), а задача, получившая
   «429», возвращается в начало очереди не более одного раза.
6. **Given** идёт пауза после «429», **When** приходит запрос домена, которого нет в кэше, **Then**
   сервер сразу (без ожидания конца паузы) отвечает HTTP 503 `archive_overloaded` с `Retry-After`
   не меньше оставшейся паузы и ставит задачу в очередь; запросы доменов, которые есть в кэше,
   по-прежнему обслуживаются мгновенно.
7. **Given** в очереди уже 100 задач, **When** приходит запрос нового домена, которого нет в кэше,
   **Then** сервер сразу отвечает HTTP 503 `archive_overloaded` с `Retry-After` и задачу в очередь
   не ставит.

### Edge Cases

- **Очень популярный домен**: число снимков главной страницы больше предела в 100 000 — сервер
  возвращает `snapshot_count = 100000`, `count_truncated = true`; первый снимок — самый ранний
  из полученных, последний снимок получается отдельным обращением «последний снимок» (через ту же
  очередь); если это обращение не удалось, весь запрос завершается соответствующей ошибкой.
- **Домен скрыт из архива по просьбе владельца** (архив отвечает «сайт заблокирован/исключён»):
  трактуется как «нет снимков» (`snapshot_count = 0`), кэшируется как успех; в журнал пишется
  отдельная пометка.
- **Снимки с ошибочными кодами ответа** (404, редиректы): учитываются в числе снимков, как и на
  странице `web.archive.org/web/*/<домен>`, на которую ведёт интерфейс.
- **Снимки по `http` и `https`, с `www.` и без**: архив хранит их как один адрес главной
  страницы — все они входят в один счётчик; адрес снимка строится из исходного адреса, записанного
  архивом.
- **Строка списка с битой датой** (не 14 цифр): строка пропускается, в журнал пишется
  предупреждение; если не осталось ни одной корректной строки при непустом ответе — `archive_error`.
- **Архив ответил 200 с пустым телом**: это «нет снимков», а не ошибка.
- **Клиент оборвал соединение во время ожидания**: обращение к архиву не отменяется, результат
  попадает в кэш.
- **Фоновая задача после ответа 202 завершилась ошибкой** (таймаут, `archive_error`, «429»):
  ошибка не кэшируется; повторный запрос клиента не найдёт ни записи в кэше, ни задачи в очереди
  и поставит новую задачу (при «429» — получит 503 по правилам паузы).
- **Задача уже выполняется в момент 15-секундного срока** (обращение к архиву началось, но ответа
  ещё нет): клиент получает 202 с `retry_after` не меньше оставшегося времени таймаута обращения.
- **Файл кэша повреждён или недоступен при запуске**: сервер стартует с пустым кэшем и пишет
  предупреждение в журнал; при невозможности записи — продолжает работать с кэшем в памяти.
- **Кэш переполнен** (более 10 000 записей): при добавлении новой удаляются записи с самым ранним
  `checked_at`.
- **Неожиданная ошибка внутри сервера** при обработке ответа архива: перехватывается, клиент
  получает `archive_error` (502), а не 500.

## Requirements *(mandatory)*

### Functional Requirements

**Эндпоинт**

- **FR-001**: Сервер MUST предоставлять эндпоинт `GET /api/wayback?domain=<домен>`, возвращающий
  историю одного домена в формате JSON (см. «Формат ответа»).
- **FR-002**: Параметр `domain` MUST нормализоваться: обрезка пробелов, удаление одной завершающей
  точки, приведение к нижнему регистру (включая кириллицу); punycode-форма `.рф`-домена MUST
  приниматься и приводиться к кириллической.
- **FR-003**: Сервер MUST отвечать HTTP 400 с кодом `invalid_domain`, не обращаясь к архиву, если
  после нормализации домен пуст, длиннее 253 символов, содержит схему, путь, порт, пробелы или
  недопустимые символы, или не принадлежит зонам `.ru`, `.su`, `.рф`.
- **FR-004**: Поле `domain` в ответе MUST содержать нормализованное имя в той форме, в какой
  домены показываются в списке сайта (`.рф` — кириллицей).

**Данные из архива и алгоритм**

- **FR-005**: Источник данных — индекс снимков веб-архива (Wayback CDX); историей домена считаются
  все снимки его главной страницы — тот же набор, что показывает `https://web.archive.org/web/*/<домен>`.
- **FR-006**: Для домена не из кэша сервер MUST выполнять одно обращение к архиву, получающее
  список отметок времени и исходных адресов снимков главной страницы (до 100 000 строк), и из него
  вычислять: `snapshot_count` — число корректных строк; первый снимок — строка с наименьшей
  отметкой времени; последний — с наибольшей.
- **FR-007**: При обращении к архиву `.рф`-домен MUST передаваться в punycode.
- **FR-008**: Адрес снимка MUST строиться как `https://web.archive.org/web/<отметка времени из
  14 цифр>/<исходный адрес из архива>`.
- **FR-008a**: Поле `date` снимка MUST быть датой его отметки времени в UTC в формате `ГГГГ-ММ-ДД`
  (снимок `20091231233000` → `2009-12-31`, без сдвига на часовой пояс сервера); клиент показывает
  её без пересчёта часовых поясов. Поле `timestamp` — та же отметка в формате ISO 8601 с `Z`.
- **FR-009**: Если строк ровно 100 000, сервер MUST выставить `count_truncated = true` и получить
  последний снимок отдельным обращением к архиву через ту же очередь.
- **FR-010**: Пустой ответ архива и ответ «сайт исключён из архива» MUST давать успешный результат
  с `snapshot_count = 0`, `first = null`, `last = null`.
- **FR-011**: Строки с некорректной отметкой времени MUST пропускаться с предупреждением в журнале;
  непустой ответ без единой корректной строки MUST давать `archive_error`.

**Кэш**

- **FR-012**: Успешный результат и результат «нет снимков» MUST кэшироваться на сервере на 7 дней
  (срок задаётся настройкой); ключ — нормализованный домен (кириллическая и punycode-формы `.рф`
  дают один ключ).
- **FR-013**: Ошибки (`archive_overloaded`, `archive_timeout`, `archive_error`) MUST NOT кэшироваться.
- **FR-014**: Запрос домена со свежей записью в кэше MUST обслуживаться без обращения к архиву
  и без постановки в очередь, в том числе во время паузы после «429».
- **FR-015**: Кэш MUST сохраняться на диск и восстанавливаться при запуске сервера; записи старше
  срока при чтении игнорируются; повреждённый или недоступный файл кэша MUST NOT мешать запуску.
- **FR-016**: Кэш MUST быть ограничен 10 000 записей с вытеснением записей с самым ранним
  `checked_at`.

**Очередь и лимиты**

- **FR-017**: Все обращения к архиву MUST проходить через единую очередь сервера (FIFO): не более
  одного обращения одновременно и не менее 1 секунды (настройка) между началами обращений.
- **FR-018**: Одновременные запросы одного и того же домена MUST объединяться в одну задачу очереди;
  все ожидающие клиенты получают её результат.
- **FR-019**: Сервер MUST ответить клиенту не позже чем через 15 секунд от получения запроса
  (настройка; меньше 20-секундного таймаута интерфейса, EXP-004). Если задача домена стоит
  в очереди или выполняется, а результат не готов к этому сроку (или оценка ожидания заранее
  превышает срок — тогда ответ отдаётся сразу), сервер MUST ответить HTTP 202 с телом
  `{"domain": <домен>, "status": "pending", "retry_after": N}` и заголовком `Retry-After: N`;
  задача MUST остаться в очереди и по завершении попасть в кэш.
- **FR-019a**: `N` в ответе 202 MUST быть целым числом секунд не меньше 1 — оценкой времени до
  готовности результата (позиция в очереди × интервал между обращениями + остаток выполняемого
  обращения); значение в теле и в заголовке MUST совпадать.
- **FR-019b**: HTTP 503 `archive_overloaded` MUST использоваться только при настоящей перегрузке:
  ответ архива «429» (FR-022), идущая пауза после «429» (FR-023), переполненная очередь (FR-020).
  Ожидание в обычной очереди MUST NOT давать 503.
- **FR-020**: Очередь MUST вмещать не более 100 задач; при заполненной очереди запрос нового
  домена MUST сразу получать HTTP 503 `archive_overloaded` с `Retry-After` (оценка времени до
  освобождения места, не меньше интервала между обращениями) без постановки в очередь.
- **FR-021**: Обращение к архиву MUST иметь таймаут 10 секунд (настройка) на соединение и ответ;
  при его превышении — HTTP 504 `archive_timeout`; автоматический повтор не выполняется.
- **FR-022**: При ответе архива «429» сервер MUST: ответить клиенту HTTP 503 `archive_overloaded`;
  приостановить очередь на значение `Retry-After` архива (ограниченное 1–600 с) или, если его
  нет, на 60 с; при каждом следующем «429» подряд удваивать паузу, но не более 10 минут;
  сбрасывать удвоение после первого успешного обращения; возвращать задачу, получившую «429»,
  в начало очереди не более одного раза.
- **FR-023**: Во время паузы запрос домена не из кэша MUST сразу получать HTTP 503
  `archive_overloaded` с `Retry-After` не меньше оставшейся паузы; задача ставится в очередь
  (с учётом FR-020).
- **FR-024**: Сетевая ошибка, ответ архива 5xx/4xx (кроме 429 и «сайт исключён») или
  неразбираемый ответ MUST давать HTTP 502 `archive_error`.

**Ошибки и журнал**

- **FR-025**: Каждый ответ с ошибкой MUST содержать поле `code` (`invalid_domain`,
  `archive_overloaded`, `archive_timeout`, `archive_error`) — основной машинный признак ошибки
  для клиента — и поле `detail` — человекочитаемое описание на русском, которое клиент MAY
  показывать, но MUST NOT разбирать. Значения `code` — стабильная часть контракта; текст `detail`
  может меняться без согласования. Стектрейсы и внутренние детали (адреса запросов к архиву,
  тексты исключений) в ответ MUST NOT попадать.
- **FR-026**: Любая непредвиденная ошибка обработки ответа архива MUST превращаться
  в `archive_error` (502), а не в HTTP 500.
- **FR-027**: Каждое обращение к архиву MUST журналироваться: домен, результат (успех / нет снимков /
  тип ошибки), длительность; каждая пауза после «429» — с её длительностью.
- **FR-028**: Логика получения истории MUST находиться в общем серверном модуле бизнес-логики,
  а эндпоинт — только вызывать её (чтобы её мог переиспользовать CLI в будущей фиче).

### Формат ответа

Успех (HTTP 200):

```json
{
  "domain": "example.ru",
  "snapshot_count": 1234,
  "count_truncated": false,
  "first": {
    "timestamp": "2009-03-15T12:34:56Z",
    "date": "2009-03-15",
    "url": "https://web.archive.org/web/20090315123456/http://example.ru/"
  },
  "last": {
    "timestamp": "2026-10-02T08:00:00Z",
    "date": "2026-10-02",
    "url": "https://web.archive.org/web/20261002080000/https://example.ru/"
  },
  "cached": false,
  "checked_at": "2026-10-28T18:40:12Z"
}
```

Нет снимков (HTTP 200): `snapshot_count = 0`, `count_truncated = false`, `first = null`,
`last = null`, остальные поля как при успехе.

В очереди, результат не готов за 15 с (HTTP 202, заголовок `Retry-After: 8`):

```json
{ "domain": "example.ru", "status": "pending", "retry_after": 8 }
```

Ошибка (HTTP 400 / 502 / 503 / 504) — признак ошибки `code`, текст `detail` только для показа:

```json
{ "code": "archive_overloaded", "detail": "Веб-архив перегружен, попробуйте позже" }
```

| HTTP | `code` / `status`    | Когда                                                     | `Retry-After` |
|------|----------------------|-----------------------------------------------------------|---------------|
| 202  | `status: pending`    | Задача в очереди сервера, результат не готов за 15 с      | да            |
| 400  | `invalid_domain`     | Домен пуст, некорректен или не из зон `.ru`/`.su`/`.рф`   | нет           |
| 503  | `archive_overloaded` | «429» от архива, пауза после «429», очередь заполнена     | да            |
| 504  | `archive_timeout`    | Архив не ответил за 10 с                                  | нет           |
| 502  | `archive_error`      | Сеть, 5xx, неразбираемый ответ, непредвиденная ошибка     | нет           |

### Согласование с 001-wayback-ui

| Ожидание интерфейса | Как выполняется |
|---------------------|-----------------|
| EXP-001 число и первый/последний снимок | FR-001, FR-006, FR-008, «Формат ответа» |
| EXP-002 «нет снимков» — не ошибка | FR-010: HTTP 200, `snapshot_count = 0` |
| EXP-003 различимые ошибки с описанием | FR-025: признак — `code`, описание — `detail`; «в очереди» — отдельный ответ 202, не ошибка (FR-019, FR-019b) |
| EXP-004 ответ быстрее 20 с | FR-019: не позже 15 с — итог (200 / ошибка) или 202 `pending` |
| EXP-005 20 одновременных запросов без перегрузки архива | FR-014, FR-017–FR-020, FR-019a; см. примечание |
| EXP-006 однозначные даты, `.рф` в кириллице | FR-008a: `date` — UTC, `ГГГГ-ММ-ДД`, без пересчёта поясов; FR-002, FR-004 |

**Примечание к EXP-005**: при пустом кэше 20 доменов Топ-20 не могут быть получены за 15 секунд
при лимите 1 обращение в секунду. Карточки, чей результат не готов к сроку, получают HTTP 202
`pending` с `retry_after` (не ошибку): задачи остаются в очереди, интерфейс повторяет запрос через
указанное время и получает результат из кэша или снова 202, пока задача не выполнится. Ошибка
`archive_overloaded` (503) в Топ-20 возможна только при «429» от архива или переполненной очереди.
Со второго открытия Топ-20 в течение 7 дней все 20 ответов приходят из кэша. Состояние «ожидание
в очереди» и автоматический повтор по `retry_after` — изменение для спецификации 001-wayback-ui,
которое вносит команда интерфейса.

### Key Entities

- **Запрос истории**: нормализованный домен (кириллическая форма для `.рф`) и его форма для
  обращения к архиву (punycode).
- **Снимок**: отметка времени (UTC, с точностью до секунды), дата снимка, исходный адрес,
  адрес страницы снимка в веб-архиве.
- **История домена**: домен, число снимков, признак усечения счёта, первый снимок, последний снимок
  (оба отсутствуют при нуле снимков), время получения из архива.
- **Запись кэша**: история домена и время её получения; свежая 7 дней; хранится на диске.
- **Задача очереди**: домен, список ожидающих клиентов, признак «уже возвращалась после 429»,
  время постановки.
- **Состояние очереди**: время последнего обращения к архиву, конец текущей паузы, текущая
  длительность паузы (для удвоения).
- **Ответ «в очереди»**: домен, статус `pending`, оценка `retry_after` в секундах (HTTP 202).
- **Ошибка истории**: машинный код `code` (основной признак), описание `detail`, HTTP-статус,
  необязательный `Retry-After`.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Для домена с известным набором снимков сервер в 100 % случаев возвращает точное число
  снимков и корректные даты и адреса первого и последнего снимка.
- **SC-002**: Повторный запрос того же домена в течение 7 дней обслуживается без обращения к архиву
  в 100 % случаев (в том числе после перезапуска сервера) и отвечает менее чем за 0,1 с.
- **SC-003**: 100 % ответов сервера на запрос истории приходят не позже чем через 15 секунд от
  получения запроса — успехом, ответом «в очереди» (202) или различимой ошибкой.
- **SC-003a**: Без «429» от архива и при неполной очереди 0 % запросов получают
  `archive_overloaded`, при любом числе одновременных запросов.
- **SC-004**: Ни при какой нагрузке сервер не делает больше одного обращения к архиву в секунду
  и ни одного обращения во время паузы после «429».
- **SC-005**: 0 ответов HTTP 500 и 0 стектрейсов в ответах при любых ответах архива (429, таймаут,
  5xx, мусор, пустой ответ).
- **SC-006**: При открытии Топ-20 с пустым кэшем все 20 доменов получают результат в кэше не позже
  чем через 1 минуту (при отсутствии «429» и ответах архива быстрее 2 с), а повторный запрос любого
  из них отдаётся мгновенно.
- **SC-007**: N одновременных запросов одного домена порождают ровно одно обращение к архиву.

## Assumptions

- Индекс снимков веб-архива доступен публично без ключа; лимит архива неизвестен точно, поэтому
  1 обращение в секунду — безопасное значение по умолчанию, вынесенное в настройку.
- «История домена» — снимки главной страницы домена (как на странице `web/*/<домен>`), а не всех
  страниц и поддоменов: это совпадает со ссылкой «Открыть в веб-архиве» в интерфейсе.
- 100 000 снимков главной страницы — достаточный предел для освобождающихся доменов; превышение
  обрабатывается как редкий случай (FR-009).
- Сервер работает в одном процессе; очередь, объединение запросов и пауза действуют в пределах
  этого процесса. Масштабирование на несколько процессов — вне scope.
- Кэш хранится в локальном файле рядом с проектом; база данных не вводится (принцип I конституции).
- Аутентификации у эндпоинта нет, как и у остальных `/api/*` сайта.
- Тесты не ходят в сеть: архив и время подменяются заглушками (принцип II конституции).
- Вне scope: интерфейс (фича 001-wayback-ui), команда CLI, история поддоменов и внутренних страниц,
  содержимое снимков, другие архивы, пакетный эндпоинт для нескольких доменов, ручная очистка кэша.
