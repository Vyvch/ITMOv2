# Контракт: история домена в веб-архиве

**Версия**: 1.2 | **Дата**: 2026-10-28 | **Статус**: согласован

**Стороны**: сервер — `specs/002-wayback-api/spec.md`; интерфейс — `specs/001-wayback-ui/spec.md`.
При расхождении любой из спецификаций с этим файлом приоритет у этого файла. Изменения контракта
вносятся только по согласованию обеих команд с повышением версии.

## Эндпоинт

```
GET /api/wayback?domain=<домен>
```

- `domain` — имя одного домена зоны `.ru`, `.su` или `.рф`, закодированное через
  `encodeURIComponent`. `.рф` можно передавать кириллицей или в punycode.
- Принимаются только домены второго уровня — ровно две метки: `example.ru`, `пример.рф`.
  Любой поддомен, включая `www.` (`www.example.ru`, `shop.msk.ru`, `www.пример.рф`), даёт
  `400 invalid_domain`.
- Сервер нормализует имя: обрезает пробелы, убирает завершающую точку, приводит к нижнему регистру.
  Схема, путь, порт и пробелы внутри имени недопустимы.
- История — снимки главной страницы домена, тот же набор, что на
  `https://web.archive.org/web/*/<домен>`.
- Ответ сервера приходит не позже чем через 15 секунд от получения запроса.

## Ответы

Тело ответа всегда JSON. Клиент различает ответы по HTTP-статусу, а ошибки — по полю `code`.

### 200 — история получена

```json
{
  "domain": "example.ru",
  "snapshot_count": 1234,
  "count_truncated": false,
  "first": {
    "timestamp": "2009-03-15T12:34:56Z",
    "date": "2009-03-15",
    "url": "https://web.archive.org/web/20090315123456/http://example.ru/"
  },
  "last": {
    "timestamp": "2026-10-02T08:00:00Z",
    "date": "2026-10-02",
    "url": "https://web.archive.org/web/20261002080000/https://example.ru/"
  },
  "cached": false,
  "checked_at": "2026-10-28T18:40:12Z"
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `domain` | string | Нормализованное имя; `.рф` — кириллицей, как в списке доменов |
| `snapshot_count` | integer ≥ 0 | Число снимков главной страницы |
| `count_truncated` | boolean | `true`, если снимков больше 100 000 и `snapshot_count = 100000` — нижняя граница |
| `first`, `last` | object \| null | Первый и последний снимок; `null` при `snapshot_count = 0`; при одном снимке совпадают |
| `first.timestamp` | string | Момент снимка, ISO 8601 в UTC с `Z` |
| `first.date` | string | Дата снимка в UTC, `ГГГГ-ММ-ДД` |
| `first.url` | string | Адрес страницы снимка в веб-архиве, всегда `https://web.archive.org/web/...` |
| `cached` | boolean | `true`, если ответ взят из кэша сервера |
| `checked_at` | string | Когда данные получены из архива, ISO 8601 в UTC с `Z` |

### 200 — снимков нет

«Нет снимков» — это успешный результат, а не ошибка. Сюда же относятся домены, которые архив
скрыл по просьбе владельца.

```json
{
  "domain": "never-archived.ru",
  "snapshot_count": 0,
  "count_truncated": false,
  "first": null,
  "last": null,
  "cached": true,
  "checked_at": "2026-10-27T09:15:00Z"
}
```

### 202 — в очереди, результат ещё не готов

Задача домена стоит в очереди сервера или выполняется, но результат не готов за 15 секунд.
Это не ошибка: задача остаётся в очереди, а результат попадёт в кэш. В том числе так сервер
отвечает, когда сам архив отвечает медленно: обращение к архиву может идти до 30 секунд
и продолжается в фоне.

```
HTTP/1.1 202 Accepted
Retry-After: 8
```

```json
{ "domain": "example.ru", "status": "pending", "retry_after": 8 }
```

| Поле | Тип | Описание |
|------|-----|----------|
| `domain` | string | Нормализованное имя, как в ответе 200 |
| `status` | string | Всегда `"pending"` |
| `retry_after` | integer ≥ 1 | Через сколько секунд повторить запрос; совпадает с заголовком `Retry-After` |

### Ошибки — 400, 502, 503, 504

```json
{ "code": "archive_overloaded", "detail": "Веб-архив перегружен, попробуйте позже" }
```

| HTTP | `code` | Когда | `Retry-After` | Пример `detail` |
|------|--------|-------|---------------|-----------------|
| 400 | `invalid_domain` | Пустое или некорректное имя, домен не из зон `.ru`/`.su`/`.рф`, поддомен (не второй уровень, включая `www.`) | нет | «Некорректный домен» |
| 503 | `archive_overloaded` | Архив ответил «429»; идёт пауза после «429»; очередь сервера заполнена (100 задач) | да | «Веб-архив перегружен, попробуйте позже» |
| 504 | `archive_timeout` | Архив не ответил за 30 секунд (приходит клиенту, который ждёт задачу в момент таймаута, например повторившему запрос после 202) | нет | «Веб-архив не ответил вовремя» |
| 502 | `archive_error` | Сетевая ошибка, ответ архива 5xx/4xx, неразбираемый ответ, непредвиденная ошибка сервера | нет | «Не удалось получить историю из веб-архива» |

- `code` — основной и стабильный признак ошибки. Новые значения добавляются только с повышением
  версии контракта.
- `detail` — человекочитаемое описание на русском. Его текст может меняться без согласования.
- Ожидание в обычной очереди никогда не даёт 503 — для него есть 202.
- В ответах нет стектрейсов и внутренних подробностей.

## Retry-After

- Передаётся в ответах 202 и 503 как целое число секунд, не меньше 1 (формат delta-seconds).
- В 202 значение совпадает с полем `retry_after` и оценивает время до готовности результата.
- В 503 значение показывает, когда имеет смысл повторить запрос: не раньше конца паузы после «429»
  или освобождения места в очереди.
- Значение — оценка, а не гарантия: после повтора возможен ещё один 202.

## Кэш сервера

- Ответы 200, включая «нет снимков», кэшируются на 7 дней. Ключ — нормализованное имя, кириллица
  и punycode для `.рф` дают одну запись. В течение срока повторный запрос отдаётся мгновенно
  с `cached: true`.
- Ошибки и 202 не кэшируются.

## Правила для клиента

1. Кодировать `domain` через `encodeURIComponent`. `.рф` передавать в той форме, в какой домен
   показан в списке.
2. Ветвиться по HTTP-статусу, а для ошибок — по `code`. Никогда не разбирать текст `detail`.
3. **200**: при `snapshot_count > 0` показывать число снимков, `first` и `last`; при
   `snapshot_count = 0` — состояние «Нет снимков». Если `count_truncated = true`, показывать число
   как нижнюю границу (например, «более 100 000»).
4. **202**: оставаться в состоянии загрузки и повторить тот же запрос через `retry_after` секунд —
   не раньше. Повторять, пока не придёт 200 или ошибка. Рекомендуемый предел — суммарно 2 минуты
   ожидания на домен, после чего показывать ошибку с кнопкой «Повторить».
5. **503 `archive_overloaded`**: показывать «архив перегружен». Автоматический повтор — не раньше
   `Retry-After`; ручной повтор пользователем разрешён в любой момент.
6. **504 `archive_timeout`** и **502 `archive_error`**: показывать соответствующую ошибку
   и кнопку «Повторить». Автоматически не повторять.
7. **400 `invalid_domain`**: не повторять.
8. Неизвестный `code`, ответ не в формате JSON или неизвестный статус обрабатывать как
   `archive_error`.
9. Поле `date` показывать как есть — это дата в UTC — без пересчёта в часовой пояс браузера.
   Для отображения `ДД.ММ.ГГГГ` достаточно переставить части строки.
10. Ссылки `first.url` и `last.url` открывать только при схеме `https:` или `http:`.
11. Все строки из ответа (`domain`, `detail`, адреса) выводить через `textContent` / атрибуты,
    а не через `innerHTML` (принцип V конституции).
12. Клиентский таймаут на один запрос — 20 секунд. Сервер всегда отвечает за 15, поэтому
    срабатывание таймаута означает сбой связи.
