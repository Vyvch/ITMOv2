## Context Pack для первого рабочего сценария

Сценарий: помощник получает diff одного PR и готовит комментарий для ревьюера.

### Факты и правила

- Стек проекта: Python 3.12, FastAPI, pytest; CI — GitHub Actions (линтер + тесты).
- Помощник обслуживает команду из 6 бэкенд-разработчиков; читатель комментария — ревьюер PR.
- Решение по PR всегда принимает человек; помощник только готовит материалы для ревью.
- Каждый риск обязан ссылаться на файл и строку из diff и содержать доказательство — что именно в изменённом коде приводит к проблеме.
- Утверждения, которые нельзя доказать по diff (версии, инфраструктура, требования), помощник помечает как вопросы, а не как риски.

### Формат входа и результата

- Вход: unified diff одного PR (текст).
- Результат: 1) краткое описание изменения (2–3 предложения); 2) не больше трёх рисков — каждый с файлом, строкой и доказательством; 3) список проверок, которые стоит запустить (воспроизводимые команды или шаги).

### Ограничения и запрещённые действия

- Запрещено: approve, merge, изменение кода, выполнение команд.
- Не больше трёх рисков; менее значимые наблюдения опускаются.
- Код не передаётся никуда, кроме одобренного LLM-провайдера (VseLLM).
- Нельзя выдавать предположения за факты: всё недоказуемое по diff — в раздел вопросов.

### Хороший пример

```text
app/api.py, create_review — обращение payload["diff"] вызывает KeyError,
если в теле запроса нет поля diff. Проверка: отправить POST /api/reviews
с пустым JSON-объектом и проверить ответ сервиса.
```

### Плохой пример

```text
Код можно улучшить. Добавьте тесты и обработку ошибок.
```

### Что пока неизвестно

- Требования к аутентификации и rate limiting для эндпоинтов сервиса.
- Максимальный допустимый размер diff и политика усечения.
- Целевой формат интеграции комментария в GitHub (комментарий к PR, check run и т.п.).

## Как использовали AI

- Для чего: заполнить AS IS-контекст и Context Pack по согласованной со студентом легенде учебного кейса; слабые места zero-shot запуска P1-01 использованы как список фактов, которых не хватало во входе.
- Тип промпта: диалог в режиме Build (уточняющие вопросы агента → подтверждение студента).
- Строка в [`prompts.md`](prompts.md): P1-01 (оценка слабых мест) — основание для фактов и ограничений Context Pack.
- Что проверил студент и какие исправления поручил агенту: студент подтвердил легенду (команда 6 человек, ожидание ревью ~1 день, стек Python 3.12/FastAPI, ограничения помощника) без правок.
