## Вопросы проверки и подтверждения

(Сгенерированы моделью внутри CoVe)
* **Вопрос 1:** Является ли проверка HMAC-подписи интеграционным тестом, или это юнит-тест? 
  * **Ответ:** Зависит от реализации, но в FastAPI это обычно Dependency, блокирующая весь роут. Проверка прохождения запроса через пайплайн FastAPI делает это полноценным интеграционным тестом.
* **Вопрос 2:** Есть ли у GitHub Webhook встроенный механизм ретраев? 
  * **Ответ:** Да, при ответе не 2xx. Значит, ошибка авторизации должна возвращать HTTP 401/403, чтобы GitHub пометил её как сбой доставки.
* **Вопрос 3:** Валидна ли для нас ошибка Rate Limit (429) от VseLLM? 
  * **Ответ:** Да, но приоритетнее закрыть дыру в безопасности (подделка вебхуков). Выбираем HMAC-валидацию как самый критичный упущенный кейс.

## Что получили (Шаг 4)

### Сценарий 4: Невалидная подпись вебхука (HMAC)
* **Связь компонентов:** GitHub ➔ FastAPI
* **Цель:** Убедиться, что сервис отклоняет фейковые запросы с неправильным или отсутствующим заголовком `X-Hub-Signature-256`.
* **Инструмент:** `pytest`, `FastAPI TestClient`.
* **Шаги:**
  1. Не мокать VseLLM (запрос должен отбиться до вызова бизнес-логики).
  2. Отправить `client.post("/webhook", json=payload, headers={"X-Hub-Signature-256": "sha256=invalid_hash"})`.
* **Ожидаемый результат:** Сервис немедленно отвечает `401 Unauthorized` (или `403 Forbidden`). Никаких внешних вызовов к VseLLM не происходит, в лог пишется `Security: Invalid webhook signature`.
