## Запрос
**Официальная документация GitHub API (Источник):**
"If you exceed your rate limit, GitHub API responds with a 403 Forbidden or 429 Too Many Requests status code. The response will include an `x-ratelimit-reset` header indicating the exact time when your limit will be restored."

**Задача:**
Основываясь строго на документации, напиши пятый сценарий интеграционного теста для нашего файла. Тест должен проверять реакцию сервиса на превышение лимитов GitHub API при попытке опубликовать комментарий. Укажи, какие статус-коды и заголовки замокать.

## Что получили

### Сценарий 5: Превышение лимитов GitHub API (Rate Limit)
* **Связь компонентов:** FastAPI ➔ GitHub API
* **Цель:** Убедиться, что сервис корректно обрабатывает блокировку по лимитам запросов, опираясь на заголовки GitHub.
* **Инструмент:** `pytest`, `pytest-httpx`.
* **Шаги:**
  1. В фикстуре `httpx_mock` задать роут `POST https://api.github.com/.../comments` с ответом `status_code=403` (или 429).
  2. Добавить в мок-ответ заголовок `x-ratelimit-reset: "1710000000"`.
  3. Вызвать `client.post("/webhook", json=payload)`.
* **Ожидаемый результат:** Сервис отвечает `202 Accepted`, комментарий не публикуется, в лог пишется `warning: GitHub API rate limit exceeded. Reset at 1710000000`.
